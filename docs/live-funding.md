# Автоматический каталог и уведомления о поддержке

Дополнено независимыми официальными источниками. Актуальная архитектура, ограничения, проверка и мониторинг описаны в [multi-source-funding.md](multi-source-funding.md). Ниже — исходная интеграция Минфина и общие настройки.

## Что подключено

Официальный портал Минфина «Электронный бюджет»: https://promote.budget.gov.ru/public/minfin/activity. Сервер загружает опубликованные отборы на субсидии, сохраняет ссылку на объявление, организатора, даты и известные категории получателей. Существующие шесть программ остаются в каталоге.

Проверка выполняется раз в 15 минут. Это периодическое обновление, не поток событий и не гарантия мгновенной доставки. Первые 1 000 карточек обновляются каждый цикл; если активные отборы продолжаются, обход расширяется до 5 000. Отдельный сохранённый курсор постепенно обходит остальные страницы. Портал содержит и архив: его общее число записей нельзя выдавать за число действующих мер.

На локальной проверке 26 сентября 2026 года источник вернул 43 370 записей, из которых первый проход импортировал 990 незакрытых отборов. Каталог вместе с прежними программами содержит 996 записей. Числа меняются со временем. Это один большой официальный источник, не все меры поддержки России.

Нет публичного SLA или договора API: структура портала может измениться. При ошибке сохраняется последняя успешная копия; статус доступен через `/api/funding/live-status`. Неизвестные условия не становятся подтверждёнными. Общий бюджет субсидии не подставляется как сумма одному получателю.

## Как отбираются уведомления

1. Пользователь добавляет бизнес и включает уведомления в настройках («Мой бизнес → Настройки»).
2. Подписка привязана к сессии браузера (заголовок `X-Opora-Session`, сервер хранит только его SHA-256). ID из произвольного тела запроса не принимается.
3. Предварительный фильтр учитывает статус приёма, известные ограничения, сумму и совпадения направления с названием отбора. После получения подробных условий проверяется территория.
4. GigaChat получает параметры бизнеса и полный доступный текст условий. Рекомендация требует обоснования с цитатами, буквально найденными в источнике. Неполные сведения, отсутствие AI и недоступный источник не создают вымышленных рекомендаций.
5. Подходящая возможность появляется в списке уведомлений в настройках приложения; «Открыть меру» открывает карточку и отмечает уведомление прочитанным. Внешняя доставка (e-mail, push, мессенджер) не подключена. Финальное соответствие требованиям и одобрение остаются у оператора программы.

Первое подключение проверяет также уже существующие активные меры. Затем проверяются новые версии записей. Предварительный поиск по названию консервативен и может пропускать релевантные программы: полнота охвата не гарантируется. Изменение только подробного текста без изменения карточки пока не создаёт новую версию уведомления.

Очередь обрабатывается каждую минуту: не более 12 проверок за проход и двух на пользователя. При большом количестве подписок обработка занимает больше 15 минут. Реестр отмеченных мер в SQLite защищает от повторных уведомлений после изменения версии. Ошибки доступны только в мониторинге.

Бизнес-логика (`funding-catalog/notifications.ts`) отделена от доставки (`funding-catalog/notification-delivery.ts`). Для будущего внешнего канала достаточно реализовать `NotificationTransport` и передать `NotificationDelivery` в `NotificationWorker`; подбор и AI-проверка не меняются. Внешняя отправка возможна только при отдельном согласии в подписке (`external_delivery`, сейчас всегда 0).

Смена параметров скрывает прежние рекомендации и отменяет ожидающие внешние отправки старого профиля. Отключение уведомлений удаляет подписку и её историю.

После добавления компании или проекта в приложении появляется поздравление, которое сохраняется на устройстве. Редактирование той же компании не создаёт повтор. В «Мой бизнес» есть удаление с подтверждением: очищаются профиль, параметры подбора, AI-контекст и поздравление. Сначала удаляются серверная подписка и сохранённая на сервере компания; при сетевой ошибке профиль остаётся и можно повторить попытку. Черновики и избранное сохраняются, но старые черновики не становятся данными новой компании.

## Настройка сервера

Используется Node.js 22 с доступным `node:sqlite` (как существующий индекс компаний). Переменные:

| Переменная | Назначение |
| --- | --- |
| `FUNDING_SYNC` | `off` отключает обновление каталога и фоновые уведомления; по умолчанию включены |
| `OPORA_FUNDING_DIR` | Постоянный каталог для `catalog.json`, `notifications.sqlite` и WAL; по умолчанию `miniapp/api-server/source-data/funding` |
| `GIGACHAT_AUTH_KEY`, `GIGACHAT_SCOPE`, `GIGACHAT_MODEL` | Серверный доступ к GigaChat |

`restart-api.cjs` сохраняет эти настройки PM2, не печатая секреты. Каталог данных не должен удаляться при деплое; резервное копирование SQLite нужно выполнять согласованно с WAL. Текущий деплой через Git не удаляет этот игнорируемый каталог.

Хранятся SHA-256 сессии браузера и разрешённые параметры подбора. ИНН, название компании и файлы в подписку не включаются.

Для портала Минфина добавлен публичный промежуточный сертификат GlobalSign, отсутствующий в выдаваемой сервером цепочке. Доверие ограничено соединением с этим источником; проверка TLS не отключается.

## Проверка реализации

- API: тесты покрывают изоляцию сессий, смену бизнеса, отключение, цитаты AI, дубликаты, outbox внешней доставки с тестовым транспортом, сохранение SQLite и блокировку параллельных обработчиков.
- Реальный источник: загрузка каталога и подробных условий проверена локально.
- Браузер (`npm run test:ux --prefix miniapp`): включение и отключение уведомлений, список уведомлений в настройках, переход «Открыть меру» с отметкой прочтения, отсутствие горизонтального переполнения.
- Переходы: прямая ссылка `?program=<id>` открывает нужную карточку после загрузки каталога; закрытая карточка не открывается повторно при обновлении.
- Внешние ответы GigaChat в автоматических тестах подменены контролируемыми ответами.

Деплой дополнительно запускает `funding-catalog/smoke-check.cjs`: проверяет настоящий источник и ответ GigaChat на условия реального отбора. Проверка не рассылает сообщения пользователям. Статус конкретного развёртывания смотрите в GitHub Actions.
